# 要件定義書

## 概要

麻雀の牌効率を学習するためのアプリケーション。ユーザーが手牌を登録し、各牌を選択した際の受け入れ枚数と受け入れ牌を表示することで、最適な打牌選択を学習できる。学習記録を保存し、後から振り返ることができる。

## 要件

### 要件1

**ユーザーストーリー:** 麻雀プレイヤーとして、手牌を視覚的に登録したいので、牌の画像を見ながら直感的に選択できるようにしたい

#### 受け入れ基準

1. WHEN アプリを起動した時 THEN システムは全ての麻雀牌の画像を表示する
2. WHEN 牌を表示する時 THEN システムは通常牌と赤ドラ牌（5m、5p、5s各1枚）を区別して表示する
3. WHEN ユーザーが牌の画像をクリックした時 THEN システムはその牌を手牌に追加する
4. WHEN 手牌が14枚に達した時 THEN システムは決定ボタンを有効化する
5. WHEN 手牌が14枚未満の時 THEN システムは残り枚数を表示し、決定ボタンを無効化する
6. WHEN ユーザーが決定ボタンをクリックした時 THEN システムは牌の選択を無効化し、ドラ選択モードに移行する
7. WHEN ユーザーが手牌の牌をクリックした時 THEN システムはその牌を手牌から削除する
8. WHEN 手牌から牌が削除された時 THEN システムは牌の選択を再度有効化し、決定ボタンを無効化する

### 要件2

**ユーザーストーリー:** 麻雀プレイヤーとして、ドラを設定したいので、実際の対局に近い状況で牌効率を学習できるようにしたい

#### 受け入れ基準

1. WHEN 手牌が確定された時 THEN システムはドラ選択画面を表示する
2. WHEN ドラ選択画面が表示された時 THEN システムは全ての牌をドラ表示牌として選択可能にする
3. WHEN ユーザーがドラ表示牌を選択した時 THEN システムは最大4枚まで選択を許可する
4. WHEN ドラ表示牌が選択された時 THEN システムは選択された牌を視覚的に強調表示する
5. WHEN ユーザーがドラ設定を完了した時 THEN システムは牌効率分析モードに移行する

### 要件3

**ユーザーストーリー:** 麻雀プレイヤーとして、登録した手牌を保存したいので、後から同じ手牌で練習を続けられるようにしたい

#### 受け入れ基準

1. WHEN ドラ設定が完了した時 THEN システムは手牌とドラ情報を一時保存する
2. WHEN 手牌が保存された時 THEN システムは牌効率分析モードに移行する
3. WHEN 牌効率分析モードに移行した時 THEN システムは手牌編集に戻るボタンを表示する

### 要件4

**ユーザーストーリー:** 麻雀プレイヤーとして、手牌の各牌の受け入れ情報を知りたいので、どの牌を切るべきかを学習できるようにしたい

#### 受け入れ基準

1. WHEN ユーザーが手牌の牌を選択した時 THEN システムはその牌を切った場合の受け入れ枚数を計算する
2. WHEN 受け入れ枚数が計算された時 THEN システムは受け入れ牌の種類と枚数を表示する
3. WHEN 受け入れ牌を表示する時 THEN システムは牌の画像と枚数を組み合わせて表示する
4. WHEN 受け入れ牌の枚数を表示する時 THEN システムは牌画像の横に「×4」のような枚数表記を表示する
5. WHEN 複数の受け入れ牌がある時 THEN システムは全ての受け入れ牌を画像付きで一覧表示する
6. WHEN 受け入れ牌の総枚数を表示する時 THEN システムは「受け入れ枚数: XX枚」として合計を表示する

### 要件5

**ユーザーストーリー:** 麻雀プレイヤーとして、分析結果を記録したいので、後から学習内容を振り返ることができるようにしたい

#### 受け入れ基準

1. WHEN ユーザーが牌を選択して分析結果が表示された時 THEN システムは分析ログを記録する
2. WHEN 分析ログを記録する時 THEN システムは選択した牌、受け入れ枚数、受け入れ牌の情報を保存する
3. WHEN ユーザーが複数の牌を分析した時 THEN システムは全ての分析結果を履歴として保持する

### 要件6

**ユーザーストーリー:** 麻雀プレイヤーとして、最適手の理由をメモしたいので、自分の思考過程を記録して学習効果を高めたい

#### 受け入れ基準

1. WHEN 牌の分析結果が表示された時 THEN システムはメモ入力用のテキストフィールドを表示する
2. WHEN ユーザーがメモを入力した時 THEN システムはメモを分析結果と関連付けて保存する
3. WHEN メモが保存された時 THEN システムはメモが保存されたことを視覚的に示す

### 要件7

**ユーザーストーリー:** 麻雀プレイヤーとして、学習セッションにタイトルを付けて保存したいので、後から特定の学習内容を見つけやすくしたい

#### 受け入れ基準

1. WHEN ユーザーが学習セッションを終了する時 THEN システムはタイトル入力フィールドを表示する
2. WHEN ユーザーがタイトルを入力して保存ボタンをクリックした時 THEN システムは手牌、分析ログ、メモを含む学習セッションを保存する
3. WHEN 学習セッションが保存された時 THEN システムは保存完了メッセージを表示する
4. IF タイトルが入力されていない時 THEN システムは自動的に日時をタイトルとして設定する

### 要件8

**ユーザーストーリー:** 麻雀プレイヤーとして、アカウントを作成してログインしたいので、自分の学習データを個別に管理できるようにしたい

#### 受け入れ基準

1. WHEN ユーザーがアプリにアクセスした時 THEN システムはログイン画面を表示する
2. WHEN ユーザーがメールアドレスとパスワードを入力した時 THEN システムはアカウント作成またはログインを実行する
3. WHEN ログインが成功した時 THEN システムはユーザー固有のデータにアクセスできるようにする
4. WHEN ユーザーがログアウトした時 THEN システムは全てのユーザーデータへのアクセスを無効化する

### 要件9

**ユーザーストーリー:** 麻雀プレイヤーとして、学習セッションの公開設定を選択したいので、他のユーザーと知識を共有したり、プライベートに保持したりできるようにしたい

#### 受け入れ基準

1. WHEN 学習セッションを保存する時 THEN システムはPrivate/Public選択オプションを表示する
2. WHEN ユーザーがPrivateを選択した時 THEN システムはそのセッションを作成者のみアクセス可能にする
3. WHEN ユーザーがPublicを選択した時 THEN システムはそのセッションを全ログインユーザーが閲覧可能にする
4. WHEN Publicセッションを表示する時 THEN システムは読み取り専用モードで表示し、編集を禁止する
5. WHEN セッション一覧を表示する時 THEN システムはPrivate/Publicの区別を視覚的に示す

### 要件10

**ユーザーストーリー:** 麻雀プレイヤーとして、自分の学習セッションを閲覧したいので、過去の学習内容を復習できるようにしたい

#### 受け入れ基準

1. WHEN ユーザーが学習履歴画面にアクセスした時 THEN システムは自分が作成した学習セッションの一覧を表示する
2. WHEN ユーザーが学習セッションを選択した時 THEN システムは手牌、分析結果、メモを表示する
3. WHEN 学習セッションを表示する時 THEN システムは読み取り専用モードで表示する

### 要件11

**ユーザーストーリー:** 麻雀プレイヤーとして、他のユーザーが公開した学習セッションを閲覧したいので、他の人の思考過程を学習に活用したい

#### 受け入れ基準

1. WHEN ユーザーが公開セッション一覧画面にアクセスした時 THEN システムは全ユーザーのPublicセッションを表示する
2. WHEN 公開セッション一覧を表示する時 THEN システムは作成者名、タイトル、作成日時を表示する
3. WHEN ユーザーが公開セッションを選択した時 THEN システムは内容を読み取り専用で表示する
4. WHEN 公開セッションを表示する時 THEN システムは編集機能を無効化し、閲覧のみ許可する

### 要件12

**ユーザーストーリー:** 麻雀プレイヤーとして、公開セッションにコメントしたいので、改善点や質問を共有して学習コミュニティを活性化したい

#### 受け入れ基準

1. WHEN 公開セッションを表示している時 THEN システムはコメント入力フィールドを表示する
2. WHEN ユーザーがコメントを入力して投稿した時 THEN システムはコメントを保存し、表示に反映する
3. WHEN コメントを表示する時 THEN システムは投稿者名、投稿日時、コメント内容を表示する
4. WHEN 複数のコメントがある時 THEN システムは投稿日時順（新しい順）で表示する
5. WHEN コメント投稿者が自分のコメントを表示している時 THEN システムは削除ボタンを表示する
6. WHEN ユーザーが自分のコメント削除ボタンをクリックした時 THEN システムはコメントを削除する
